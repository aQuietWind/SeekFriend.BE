# 什么？你说你想学项目？那这个项目恐怕无法满足你了。
### 我为什么写了这个项目？
因为我太闲了，以及想要熟练适应下PostgreSQL的语法和LangChain4j的用法。
### 该不该学习这个项目？
<p>我的回答是不怎么该,如果你学习过我的上一个项目SeekFood,你就会觉得略微眼熟,但又有所不同。</p>
<p>因为这个项目你可以看作是SeekFood的系统架构优化版本,最为主要的优化就是将Util模块与Nacos配置类的基础对象进行重新拆解组合,实现了服务模块使用上的极致简化。如果你读过我的SeekFood的话,那么你会发现：原先某些Util方法需要6~7个参数,现在甚至可以做到只需要1个参数即可。</p>
<p>除了上述的改进,还有一个不同的是,我将Util包进行了Spring Bean化,并且引入了一个新的思想：彻底隔离。在这里，服务模块引用Util包时,直接使用即可，不需要顾及过程，只用关注结果。比如RedisUtil，内部直接引用RedisTemplate,而服务模块不需要引入如何与Redis相关依赖，因为Util模块已经解决好了一切。
你问我有什么用？最重要用法是可以在依赖版本大更新时，只需要重新更改Util模块下的代码，即可适配整个微服务系统，不再需要满系统的查找与更新代码。</p>

#### 总而言之，我不推荐你学习这个项目，如果可以，你还是看看另外一个项目SeekFood吧~
